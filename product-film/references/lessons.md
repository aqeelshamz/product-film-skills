# Lessons: every correction an owner had to make

Each entry gives what the owner said (or what broke), what was wrong, and the rule that prevents it. They come from
one long launch film (a desktop-widget app, here called Nimbet, whose widgets the buyer's own AI builds) that went through more than
30 rounds of review, plus the website work around it. Product details are examples; the rules are general.

Read the whole file before each stage, and again before each review you send. Check the film against every rule in
the stage you're in, not only the one the owner last mentioned.

---

## 1 · Process and reviews

| Owner said | What was wrong | Rule |
|---|---|---|
| "before rendering let me review" | A full render was about to start before the owner had seen the plan or a still. | Plan → stills → 30 fps draft → final. Never spend a 30-minute render on something the owner hasn't seen as stills. |
| "I have changes" / "wait i will tell you more" | Edits started while the owner was still listing changes. | When the owner says more is coming, stop and wait. Collect the full list, repeat it back as a numbered list, then work. |
| "give me a draft with frames like a storyboard … ill review them and decide" | The voiceover was written and recorded straight onto the film. | Every script (picture or voice) goes to the owner on a storyboard of REAL frames before anything is recorded or rendered. |
| "give me some different directions … so that i can decide" | One direction was presented as the answer. | When the story or message is open, show 2–4 directions side by side, each with its trade-off and risk, plus your pick. |
| "go with all your picks" | (approval) | When the owner approves your picks, log them as decisions and move on; don't re-ask. |
| (website session) owner rambled about many ideas | Each sentence was about to become a feature. | Turn a ramble into directions with trade-offs. Implement only what's chosen. |
| "is there any custom built widgets in the video?" | The film showed only stock gallery items, the opposite of the product's promise. | Before building, list what the film must PROVE about the product. Each proof needs a shot. |
| "please refer to the latest website hero section" | The film used an older look and older characters than the live site. | Before designing, open the live product, site and brand files. The film matches what a buyer sees today. |
| "the launch film looks a bit faster" | Pace was set for the builder, who knows every line. | Pace for a first-time viewer: hold every line until a slow reader finishes it. Add 15–25 % when in doubt. A pacing warp (holds + slow factor) is cheaper than retiming every shot. |
| "Render final" | (approval) | Only now do the 60 fps motion-blur render. Then send it and say what wasn't checked. |

## 2 · Reference study ("reverse engineer this video")

| Owner said | What was wrong | Rule |
|---|---|---|
| "something similar to this in our design style … but transitions and motions could be borrowed" | (the brief) | Borrow the reference's GRAMMAR: cut timing, camera pushes, how one shot hands to the next, typing, pace, where the beat drops. Never its content, product shape, colours, characters, words or story. |
| "very bad recreation" (1st attempt) | The film was minimal mockups in generic motion, so it read as "vibe-coded", "made with Claude", and not as a study of the reference. | Measure the reference (cuts, holds, push rates, the drop, typing speed) frame by frame and write the numbers down. Every borrowed move names its source time in the reference. |
| "use the reanimate skill" | The study was done from memory of a single watch. | Use tools: extract frames, build contact sheets, read EVERY sheet, measure. |
| (public reaction to another launch) | A launch video that was obviously AI-made drew public mockery. | If a viewer can tell AI made it, the product looks cheap. Tells: identical easing everywhere, centred everything, stock icons, synthesized beeps, scene-describing narration. |

## 3 · Story and message

| Owner said | What was wrong | Rule |
|---|---|---|
| "same numbers every day" sounded like analytics software | The problem statement belonged to another product category. | State the viewer's pain in their own life, in words that don't describe a different kind of product. Test: what would a stranger think we sell after this line? |
| The "Your AI" screen was unclear; people may think Nimbet provides the AI | Abstract labels ("Your AI") instead of the real thing. | Show the real tools by name and logo (Claude Desktop, a real dashboard). Remove every chance to misread who does what. |
| "'Ask the AI you already pay for.' and then 'It's called Nimbet.' do people think is it the AI called Nimbet?" | Line order made the product sound like the AI. | Check every adjacent pair of lines for a wrong reading. The product's name must attach to what the product is ("Nimbet puts it on your desktop"), never to the thing before it. |
| "20 s is too short; show more personas" | Too short to show range. | A film whose message is "it does what YOU need" needs several kinds of people and about 45–65 s. |
| "it should be more than 6, otherwise it feels very stuck" (personas) | Too few characters made the persona section feel static. | Range shots need enough variety to feel endless: 8+ personas, each in its own full-screen card, plus a wall of many items. |
| "we also need a shot … a bunch of different custom widgets … Include game widgets too … fun elements … pets" | All widgets were serious dashboards. | The range shot mixes work, life and fun (games, pets, stickers). Fun items show the ceiling of what's possible. |
| "widgets are interactive right?" / "widgets should be able to." / "do it" | The film wanted to show something the product couldn't do yet. | If a shot needs a capability the product lacks, the owner decides: build it in the product (and log the decision) or cut the shot. Never fake it. |
| "there are no pets in the product" (then, on a second look: the shot was showing custom widgets people built) | The narration named a pet before the product had one in the gallery; then it turned out the shot showed custom widgets people built. | Before writing a line about a shot, check what the shot ACTUALLY shows and why it is there. When unsure, ask the owner what a shot means. |
| (website) "show custom, highly personal widgets, not default ones" | Generic examples. | Show examples a specific person would build for themselves (their exam countdown, their store's orders), not the defaults any app ships. |
| (website) "widgets are live, so no live dot" | A decorative "LIVE" badge. | Don't add UI chrome that the real product doesn't have. |
| (website) "show real screenshots and videos to build trust" | Illustrations stood in for proof. | Real recordings and screenshots beat illustrations wherever trust matters. |

## 4 · Realism of the picture

| Owner said | What was wrong | Rule |
|---|---|---|
| "Dashboards were minimal mockups; they need detail and real logos" | Simple boxes with icon-font glyphs. | Recreate real dashboards (Stripe, GitHub, Shopify…) at real density: real nav, real tables, real logos from the brand's own site. |
| "all the widgets look too simple … minimal, vibe-coded … use actual logos instead of icon-font glyphs" | The product's own widgets were sparse. | Product UI in the film is RICHER than a mock: real data shapes, charts, labels, states, real brand marks. If the product can't render a brand logo, add that ability (it was: "Allow logo URLs"). |
| "try to include some real desktop background wallpapers" | Flat gradient backgrounds. | Use real, licensed wallpapers (and credit them). |
| "try to recreate windows, mac, android home screens in as much detail as possible" | Generic window chrome. | Real OS chrome: menu bar, dock/taskbar, real system fonts' sizing, clock, real app icons. |
| "what are these icons? Stripe doesn't even have a Mac app" | App icons for apps that don't exist on that OS. | Only show app icons that exist on that platform (Stripe has no Mac app; use apps that do). Check each one. |
| "you don't know how big it would be on an Android screen" / "phone is not a desktop" / "refer pixel's home screen" | Desktop-sized widgets were crammed on a phone. | Phones use the platform's real grid and sizes (Pixel: 4–5 columns, dp sizes, real launcher icons, search bar, dock). Render phone widgets with the product's own phone renderer, at real size. |
| "also use real icons for the phone" | Placeholder icons. | Real launcher icons (licensed/nominative), real status bar. |
| "the last android screen widgets look stacked" | Widgets overlapped. | Lay out like a real home screen: grid cells, no overlap, gutters. |
| "fix this overlap" | Elements overlapped in a frame. | Check every frame at 1–1.5 s steps for overlaps before sending. |
| "logo at 0:12 is cut at bottom" | Clipping. | Check every frame for clipped elements, especially logos and text near edges. |
| "what are the frames at 0:10–0:13?" | Broken/blank/half-built frames during a transition. | Review transitions frame by frame (contact sheet at 10–15 fps), not only shot midpoints. |
| "like how we did in the site, show the animated toy-like mascot … for each persona" | Personas were text labels. | Reuse the brand's existing characters; make new ones in the same style (12-frame sprite sheets). |
| "what are these icons?" (again, generalised) | Look-alike glyphs for real brands. | Real brand marks only, never an icon-font approximation. Add a nominative-use notice while they're on screen. |

## 5 · Motion and text

| Owner said | What was wrong | Rule |
|---|---|---|
| "0:10-0:11 text transition is not at all smooth" | Words popped / jumped as the line re-laid out. | Lay words out at their FINAL width from the start (invisible until shown) so nothing shifts as words arrive. Ease every move at both ends. |
| "0:10-0:11 text transition is too fast. i cannot even complete reading" | Text left before it could be read. | Reading time: about 0.3 s per word + 1 s, minimum 1.5 s on screen at full opacity. |
| "the prompt animation looks fading instead of typing. pls make it look like typing in keyboard" | Text faded in. | Typing = one character at a time at irregular human speed (fast bursts, pauses at spaces/punctuation), a blinking caret, the camera following the caret. Never a fade or a wipe. |
| "the launch film looks a bit faster" | Overall pace. | See §1. |

## 6 · Sound

| Owner said | What was wrong | Rule |
|---|---|---|
| "the SFX sounds like absolute AI slop" | Synthesized beeps, whooshes and ticks on every cut. | Use real recorded samples (e.g. Kenney CC0 packs: UI, interface, impact). |
| "Yes, use Kenney" / "Sounds good" | (approval) | About 20 cues in a minute, placed only on real on-screen events (a click, a widget landing, a key moment). No typing ticks on every letter, no whoosh on every move. |
| "Keep it dry" | (choice) | Ask whether to add a music bed; don't assume. Dry (voice + sparse SFX) is a valid, often better, choice. |

## 7 · Voiceover writing

| Owner said | What was wrong | Rule |
|---|---|---|
| "your revenue. your PRs, your exams. your this. your that." / "absolute AI slop" | A list of "your X, your Y" plus triads. | No "your X, your Y, your Z" lists, no triads, no "not X but Y". Write like a person talking to one friend. Use copywriting + humanizer skills. |
| "make sure the voiceover suits the video frames" | Lines didn't match what was on screen. | Each line is written against the frames it plays over. When the screen shows words, the voice says those words at that moment, or stays silent. |
| "do the silence makes awkwardness?" | Long gaps. | Small gaps (0.5–1.5 s) on a busy picture are fine; check with the owner whether long ones feel awkward. Don't fill every second. |
| "instead of a scene description, say something helpful to the viewer" | The voice described the picture ("Here, a founder builds…"). | The voice adds what the picture can't: why it matters to the viewer, how it works, what it costs them. Never narrate the picture. |
| "If viewer is listening with their eyes closed, he will be confused" | Lines only made sense with the picture. | Eyes-closed test: the voice alone must tell a coherent story. Read the transcript with no picture before sending. |
| "you kept continuing with emphasizing on the 'key'" | One word repeated in line after line. | Don't lean on one word; check the transcript for repeats. |
| "Widgets gather … can you give a short voice over for this one too, if it doesn't make it boring?" | A section was left silent by default. | Offer a short line for every section, and say when silence is better and why. |
| "Instead of 'Someone', 'A student', 'A developer', address the viewer directly … sounds like we are pitching to an investor" | Third-person persona lines. | Speak to the viewer: "you", "your store", not "a seller". |
| (two drafts rejected as slop) | Proposing "no voiceover" as a way out. | Never give up on a hard requirement by proposing to drop it. Write better. |

## 8 · Pronunciation

| Owner said | What was wrong | Rule |
|---|---|---|
| "in the voiceover, how would it pronounce nimbet?" | Assumed the engine would say it right. | Ask the owner how the name is said before recording. |
| "'NIM-bet'" / "'nim bet'" / "i mean nimbet, one word" / "this one sounds nimet" | Several spellings were tried in one take, which also shortened the take. | Test with short clips, one per spelling ("Nimbet", "Nim-bet", "Nimbbet"…), name each file by its spelling, let the owner pick. Use the winning respelling everywhere (and save it to memory). |

## 9 · Technical mistakes (cost rounds of review)

| What broke | Rule |
|---|---|
| CSS file served without its MIME type, so styles silently didn't load in the render | The render server maps `.css`, `.js`, `.woff2`, `.svg`, `.png`, `.webp`, `.json` MIME types. |
| `el.className = 'x'` wiped classes the engine had set | Use `classList.add`. |
| A widget's CSS class `w` also matched the film's word spans | Scope product CSS under a unique root class; use unique class names in the film. |
| White blank frames at the start of a shot | Every shot's first frame must already show content; check `t0 + 1 frame` stills. |
| The nominative-use notice was missing on one shot with logos | Every shot showing a brand mark shows the notice; check them all. |
| `sed` with `&` in the replacement corrupted HTML | Edit HTML/JS with the Edit tool or a script, never sed with unescaped `&`. |
| zsh didn't split `set --` arguments in a loop | Run multi-argument loops under `bash -c`. |
| Kenney returns 403 to curl | Get signed links from the browser: `fetch('https://kenney.nl/download-link/'+hex('assets/<pack>'))` in the page. |
| ChatGPT mascot sheets came back with a painted checkerboard or a black background | Retry in a fresh chat; ask for 12 frames in a 4×3 grid on plain white; strip the halo when packing. |
| A phone snapshot was taken before its images loaded | Wait for images (decode) before snapshotting; redraw. |
| A composited 3D layer kept the previous frame's raster | Re-insert the 3D view each frame (`insertBefore`), never leave it cached. |
| Embedded CSS animations ran on wall-clock time, so frames differed per render | Pause them and drive with `animation-delay: calc(-1s * var(--t))`. |
| Layout measured inside `run()` read the previous frame's layout | Measure in `after()` or once at load. |
| Fish Audio: 500-byte limit per call and per-byte credits | Record per section, check credits first, keep takes short. |
| Flag named `P` for portrait clashed with a person variable `P` | Use distinct, unmissable names for format flags (`PT`). |
| A 9:16 change altered 16:9 output | Prove 16:9 unchanged: PSNR = inf on a fixed set of stills before vs after. |
